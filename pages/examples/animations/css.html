Animating the lifecycle with CSS

Every step of a lazily loaded component's life is exposed as an attribute (or a platform pseudo-class), so most of the polish — skeletons, spinners, fades, error states — needs no JavaScript at all. This page documents the CSS side of ce-autoloader; the view transition demo covers the the advanced morphing animation.

Default CSS selectors

Selector When it matches
:not(:defined) the tag is on the page but not registered yet
[ce="loading"] the module is being fetched
[ce="defined"] the module resolved and the element upgraded
[ce="error"] loading or defining failed

Use CSS Transitions to animate state changes

Use css transitions to seamless animate between component states

A transition declared only inside :not(:defined) will not run. The browser reads transition from the new computed style, and that rule stops applying the moment the element becomes defined. A workaround is to use a class in the webcomponent, and declare the transition on that class instead. 
.ce                { transition: all 1s ease-out; opacity: .25; }
.ce[ce="loading"]  { opacity: 0.75; }
.ce[ce="defined"]  { opacity: 1; }
This is a banner message.

Use CSS animations for the last defined state

The defined state is trickier to animate, because the element is replaced with a new node. Use @keyframes to animate, and calc-size() to set the height of the element to a fixed value, so it can grow nicely the boundary box. 


keyframes pop-in {
  from { opacity: 0; }
  to   { opacity: 1; }
}
.ce[ce="defined"]  {
  animation: pop-in 1.5s ease-out;
  height: calc-size(auto, size);
}
