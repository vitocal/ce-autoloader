Animating the lifecycle with CSS

Every step of a lazily loaded component's life is exposed as an attribute (or a platform pseudo-class), so most of the polish — skeletons, spinners, fades, error states — needs no JavaScript at all. This page documents the CSS side of ce-autoloader; the view transition demo covers the morphing side.

1. The states you can style

Selector When it matches Owned by
:not(:defined) the tag is on the page but not registered yet the platform
[ce="loading"] the module is being fetched ce-autoloader
[ce="defined"] the module resolved and the element upgraded ce-autoloader
[ce="error"] loading or defining failed ce-autoloader

:defined / :not(:defined) are the platform's own state and also cover elements the registry never loaded (a component defined by someone else, one inserted after its definition). ce="…" is the richer, loader-owned state: it distinguishes loading from defined from error. Style the platform state for layout, the ce state for the story.

slow loader (3 s) Watch: dashed placeholder → shimmer → component.

2. Transitions between the states

The element is the same node while its state changes, so a plain CSS transition interpolates the swap — no View Transitions API involved. 

:not(:defined)  { opacity: .55; outline: 2px dashed teal }
[ce="loading"]  { opacity: 1;   outline-color: transparent }
[ce="defined"]  { outline-color: teal }

/* Declare the transition on the element (or on the state you move *to*). */
nord-button { transition: opacity 400ms, outline-color 400ms }

Gotcha: a transition declared only inside :not(:defined) will not run. The browser reads transition from the new computed style, and that rule stops applying the moment the element becomes defined.

3. Animating when there is nothing to transition

A component that is inserted already defined upgrades synchronously: no state change happens, so transition has no previous value to interpolate. Use an animation (keyframes) instead — it runs when the rule starts matching, including the first frame after insertion. 

.card[data-animate="keyframes"] { animation: pop-in 400ms ease-out both }

4. Is @starting-style useful here?

Yes — but not for the state swap above. @starting-style supplies the first style of an element that appears directly in its final state, which is exactly the situation a transition cannot handle on its own. Reach for it when you want a transition (rather than a keyframe animation) for an element that is created or revealed — for instance a component inserted after its definition. 

.card[data-animate="starting-style"] { opacity: 1; translate: 0; transition: opacity 400ms, translate 400ms }

@starting-style {
  .card[data-animate="starting-style"] { opacity: 0; translate: 0 8px }
}

Compare the three buttons above: animation and @starting-style fade the card in, the third one pops. Two caveats worth knowing:

  • the transition must still be declared on the element (or in a rule that keeps matching);
  • @starting-style only supplies the starting style — the interpolation is still a transition, so it honours prefers-reduced-motion like any other.

5. Entering and leaving display: none

This is where @starting-style is required: display is a discrete property, so it needs transition-behavior: allow-discrete to animate at all, plus the starting style to animate into. 

.reveal {
  display: block; opacity: 1;
  transition: display 400ms allow-discrete, opacity 400ms, translate 400ms;
}
.reveal[data-hidden] { display: none; opacity: 0; translate: 0 -8px }

@starting-style { .reveal:not([data-hidden]) { opacity: 0; translate: 0 -8px } }
I fade in and out instead of flickering.

6. CSS animations and the View Transitions API

With transition: true ce-autoloader wraps each definition in startViewTransition(), which morphs the placeholder into the component (layout included) and batches a whole batch of definitions. deferDefine (on by default) is what lets a component that registers itself — a module calling customElements.define at import time — join that morph instead of upgrading early.

  • View transitions for the placeholder → component morph, and for route or state changes where layout moves.
  • CSS transitions & animations (this page) for everything local: skeletons, spinners, fades, error states. They work in every browser and cost nothing.
  • Both compose: the morph moves the box, the CSS fades its contents.

Element-scoped view transitions are Chromium-only today, which is why the CSS-only path matters: it is the animation every user gets.
