About

This library acts as a centralized catalog for your web components, designed to maximize performance by automatically lazy-loading components only when and if they are actually needed on a page. It's remarkably lightweight (just 5kb gzipped) and completely framework-independent, making it an ideal choice for enhancing static sites or adding interactivity to backend-driven and SSR applications.

  • Universal: Anything that exports web components will work (React, Vue, Svelte, Lit, etc.)
  • Smart Loading: Use the on attribute to trigger loading based on specific events, such as on="visible" for scroll-triggered loading or on="interaction" for user clicks.
  • Polished UI: Seamlessly manage how elements enter the page using standard CSS Animations or the modern View Transition API
  • Zero Friction: The library is highly ergonomic with no dependencies, ensuring it stays fast and easy to integrate into any existing workflow.

Get started

  1. Install ce-autoloader via npm/CDN
  2. Declare your component catalog in javascript
  3. Sprinkle your <components /> across your page, or multiple pages
  4. Call registry.discover() when it's appropriate!

Activation Triggers (Loading Strategies)

The on attribute defines the strategy for when a component is activated. By default, components use the visible strategy to maximize initial performance.

visible (Default)
Lazy-loading via Intersection Observer. Components are downloaded and defined only when they enter the viewport. Perfect for content "below the fold" to keep initial page weight low.
interaction
Hydrate on demand. The module is fetched when a user clicks or touches the element. Ideal for heavy UI widgets like maps, complex editors, or modal content.
eager
Immediate activation. Downloads the module as soon as the loader discovery starts. Use this for critical "above the fold" components like navigation headers or hero sections.
*custom*
Manual/Programmatic mode. You can specify any custom string (e.g., on="lazy-load") and trigger it manually via registry.upgrade('lazy-load').

Dynamic Resolvers (Wildcard Loaders)

For large-scale design systems like Nord Health, Shoelace, or Shadcn, manually registering dozens of components is tedious and error-prone.

Dynamic Resolvers (or Wildcard Loaders) solve this by allowing you to register a function that "resolves" any tag matching a specific pattern.

In this example, we registered a resolver for the nord-* namespace. When the browser encounters <nord-qrcode>, the loader automatically fetches the correct module from the CDN.

  • No Monolithic Bundles: Only the components used are ever downloaded.
  • Automatic Discovery: New components added to the HTML are resolved instantly without updating JS.
  • Industry Standard: Follows the same "Resolver" pattern used by modern build tools and auto-import plugins.

Here is an example of a Wildcard Resolver for the Nord design system:

/**
 * Pattern-based Resolver for Nord Health components
 */
"nord-*": async (full_name) => {
    // 1. Extract the specific component name (e.g., 'qrcode' from 'nord-qrcode')
    const [, namespace, name] = full_name.match(/^([a-z]+)-(.*)/);

    // 2. Resolve the module URL (dynamic import)
    const module = await import(/* @vite-ignore */ `https://esm.sh/@nordhealth/components/lib/${capitalize(name)}.js`);

    // 3. Define the component if not already registered
    if (!customElements.get(full_name)) {
        customElements.define(full_name, module.default);
    }
    return module
},

Entrance Lifecycle & Transitions

Web components shouldn't just "pop" into existence. ce-autoloader provides a robust lifecycle state machine that allows you to style components as they transition from placeholders to interactive elements, effectively eliminating Cumulative Layout Shift (CLS).

The Discovery Lifecycle

Every component managed by the registry moves through three distinct visual states:

:not(:defined)
Placeholder State. The custom element is in the DOM but the browser doesn't know its behavior yet. Use this to set min-height or aspect-ratio to reserve space on the page.
[ce-loading]
Activation State. Triggered when the library begins fetching the module. This is the perfect time to show a Skeleton Loader or a progress indicator.
[ce-defined]
interactive State. The component is defined and upgraded. Use this to trigger a final "fade-in" or entrance animation.

CSS Transitions

Use the following css as a starting point:


/* 1. Initial State: hidden */
:not(:defined) {
	min-width: fit-content;
	min-height: 24px;
	display: block;
	visibility: visible;
	outline: 2px dashed teal;
}

/* 2. Loading State: maybe a skeleton or a spinner? */
[ce-loading] {
	display: block;
	position: relative;
	overflow: clip;

	&::after {
		content: '';
		position: absolute;
		top: 0;
		left: 0;
		width: 100%;
		height: 100%;
		animation: shimmer 1s ease-out infinite;
		background: linear-gradient(to right, transparent 10%, #0006 50%, transparent 90%);
		background-size: 100% 100%;
	}
}

/* 3. Final State: fade in */
[ce-defined] {
	display: block;
	animation: fade-in 3s ease-out 1;
}

Native Telemetry & Insights

Performance is built into the core. ce-autoloader uses the native User Timing API to provide granular metrics for every stage of your components' lifecycle. This allows you to quantify the exact impact of your loading strategies on Core Web Vitals.

Built-in Performance Marks

Every component activation generates high-resolution timestamps visible in the Performance Tab of your browser's DevTools.

  • load:tag-name: Total time spent fetching the module.
  • define:tag-name: Time taken to register with customElements.
  • transition: Time spent during the view transition animation.

Integration Ready

Because we use standard browser APIs, you can programmatically access these metrics and pipe them to your existing APM tools (Datadog, New Relic, etc.). 


// Export all component load times to your analytics
const metrics = performance.getEntriesByType('measure')
    .filter(e => e.name.startsWith('load:'));
