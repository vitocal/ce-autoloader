ce-autoloader

Load web components on demand, if and when they're used in the page.

Demo

About

This library acts as a centralized catalog for your web components, designed to maximize performance by automatically lazy-loading components only when and if they are actually needed on a page. It's remarkably lightweight (just 5kb gzipped) and completely framework-independent, making it an ideal choice for enhancing static sites or adding interactivity to backend-driven and SSR applications.

  • Universal: Anything that exports web components will work (React, Vue, Svelte, Lit, etc.)
  • Smart Loading: Use the on attribute to trigger loading based on specific events, such as on="visible" for scroll-triggered loading or on="interaction" for user clicks.
  • Polished UI: Seamlessly manage how elements enter the page using standard CSS Animations or the modern View Transition API
  • Zero Friction: The library is highly ergonomic with no dependencies, ensuring it stays fast and easy to integrate into any existing workflow.

Get started

  1. Install ce-autoloader via npm/CDN
  2. Declare your component catalog in javascript
  3. Sprinkle your <components /> across your page, or multiple pages
  4. Call registry.discover() when it's appropriate!

Controlling when components are loaded

The on attribute controls when the component is loaded. By default, it's visible.

visible
Loaded when the element is visible in the viewport
interaction
Loaded when the element is interacted(clicked)
eager
Loaded when the element is encountered at DOM
*anything*
Manual mode, you should call registry.upgrade('*anything*')

Namespaced Components

We can import a whole external library of components by using namespaced components

In this page, we registered everything under nord-* namespace, so any component like nord-qr-code will automatically load! There's no need to declare/import each component manually.

Heres the full loader for nord design system


/**
 * Nord Health design system
 */
"nord-*": async (full_name) => {
    const [, namespace, name] = full_name.match(/^([a-z]+)-(.*)/);
    const module = await import(/* @vite-ignore */ `https://esm.sh/@nordhealth/components/lib/${capitalize(name)}.js`);
    if (!customElements.get(full_name)) {
        customElements.define(full_name, module.default);
    }
    return module
},

Animated components 💪🤩💪

Components doesn't just appear from nowhere, they are animated as they enter the DOM to have a smooth loading and avoid layout shifts.

Each component goes through a lifecycle of not-defined → ce-loading → ce-defined, that can be customized in css.

We can use these attributes in css to create a smooth loading with transitions.

Component discovery lifecycle

:not(:defined)
Initial state. The component is in the DOM but not defined yet.
[ce-loading]
Loading state. We are currently fetching/importing the module.
[ce-defined]
Final state. The component has been defined and upgraded.

CSS Transitions

Use the following css as a starting point:


/* 1. Initial State: hidden */
:not(:defined) {
	min-width: fit-content;
	min-height: 24px;
	display: block;
	visibility: visible;
	outline: 2px dashed teal;
}

/* 2. Loading State: maybe a skeleton or a spinner? */
[ce-loading] {
	display: block;
	position: relative;
	overflow: clip;

	&::after {
		content: '';
		position: absolute;
		top: 0;
		left: 0;
		width: 100%;
		height: 100%;
		animation: shimmer 1s ease-out infinite;
		background: linear-gradient(to right, transparent 10%, #0006 50%, transparent 90%);
		background-size: 100% 100%;
	}
}

/* 3. Final State: fade in */
[ce-defined] {
	display: block;
	animation: fade-in 3s ease-out 1;
}

Observability & Performance

Observability is already built-in to the registry, and allows measuring the time-to-load of each component. With native `performance` integration, it shows in devtools performance panel and can be exported to your observability metrics as usual.

You can access the metrics at performance.getEntriesByName('load:my-component') or performance.getEntriesByType('measure')
